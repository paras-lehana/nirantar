# Synthetic plant generator (Nirantar)

You generate **fully synthetic** data that feels like a real plant. Never copy real company, supplier or person data.

## Inputs to confirm (use defaults if the user doesn't say)
- Target database (default `NIRANTAR`, schemas `RAW, CORE, ML, APP, AI, SIM, OPS`), warehouse (default `NIRANTAR_WH`, X-Small).
- Industry pack(s): `AUTO_COMPONENTS` (machining, forging) and/or `CEMENT` (grinding, packing); `FMCG_BOTTLING` optional.
- History days (default 75) and grain (default 5 min history, 1 min live).
- Seed (default 42) — same seed ⇒ identical data.
- If the project has a data contract file (e.g. `@nirantar/docs/data-model.md`), it **overrides** this skill's defaults.

## Procedure
1. Read `references/physics.md` (signal baselines, ISO 10816 zones, degradation shapes, sensor faults) and
   `references/enterprise-shape.md` (sites, lines, asset classes, seeded insight patterns, hero scenario).
2. Create master data in a stored procedure `SIM.GENERATE_ENTERPRISE(seed)` — ontology dims first, then ERP, then CMMS
   masters. Give every asset `layout_x/layout_y` for a floor-plan twin.
3. Create `SIM.GENERATE_HISTORY(days, seed)` with **set-based SQL** (`TABLE(GENERATOR(ROWCOUNT=>…))`, `SEQ8`,
   `UNIFORM`/`NORMAL` with seeds, window functions). Process per site if needed; never loop row-by-row in Python.
   Order: failure-episode schedule → telemetry (baseline + daily/shift cycles + noise + episode ramps + sensor faults)
   → machine states/alarms → work orders, parts usage, component installs (supplier lots) → production & OEE counts →
   tech notes (EN + Hinglish).
4. Create `SIM.GENERATE_DOCS()` for manuals (symptom → cause → action tables), SOPs (LOTO), supplier quality reports,
   shift logs.
5. Create `SIM.SCENARIO_CONTROL`, `SIM.EMIT_TICK()` (next minute for every tag, applies active scenarios, self-stops
   after 120 ticks per activation) and `SIM.RESET_DEMO()` (deterministic).
6. Save every source file into the workspace folder the user names (default `nirantar/01_data/`).
7. **Validate** and report a compact table: row counts per table, failure episodes by mode, OEE by site, FK orphans (must
   be 0), % healthy time in ISO zone A/B (≥ 85 %), seeded patterns detectable (one SQL each).

## Rules
- Keep cost low: X-Small warehouse, ≤ ~12 M telemetry rows by default; tell the user the estimated credits before running
  anything bigger.
- Deterministic: all randomness seeded; `RESET_DEMO` must reproduce the hero numbers exactly.
- Sensor faults (flat-line, stuck-at-zero, spike, dropout) are **labelled** in a hidden column `_fault_type` so tests can
  prove they never become failure alerts.
- Label everything synthetic: table comment `'SYNTHETIC — generated by nirantar-synthetic-plant v1.0'`.
